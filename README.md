# Notes REST API (Node.js + Express + MongoDB)

RESTful API для управления персональными заметками с системой аутентификации и авторизации пользователей на основе сессий и защищённых HTTP-only cookies. Подключение к облачной базе данных MongoDB Atlas реализовано через ODM Mongoose. Поддерживаются полные CRUD-операции с привязкой к текущему пользователю (`userId`), фильтрация по тегам и тексту, пагинация, строгая валидация данных через `celebrate` (`Joi`) и централизованная обработка ошибок.

**Live Demo (Render):** https://nodejs-hw-ozrn.onrender.com

---

## 🛠️ Технологический стек

- **Node.js & Express** — серверная платформа и маршрутизация
- **MongoDB & Mongoose** — облачная NoSQL база данных, связи между коллекциями (`ref`), индексация и моделирование схем
- **bcrypt** — криптографическое хеширование паролей пользователей
- **cookie-parser** — парсинг и работа с HTTP-only cookies (`accessToken`, `refreshToken`, `sessionId`)
- **celebrate & Joi** — декларативная валидация параметров маршрута, query-параметров и тела запроса
- **http-errors** — генерация стандартизированных HTTP-ошибок
- **pino-http & pino-pretty** — структурированное логирование входящих запросов
- **dotenv** — управление переменными окружения
- **cors** — настройка политики кросс-доменных запросов

## ⚙️ Установка и локальный запуск

1. **Клонируйте репозиторий и перейдите в ветку `04-auth`:**

```bash
git clone https://github.com
cd nodejs-hw
git checkout 04-auth
```

2. **Установите зависимости:**

```bash
npm install
```

3. **Настройте переменные окружения:** Создайте файл `.env` в корне проекта и добавьте следующие параметры:

```env
PORT=3000
MONGO_URL=ваша_строка_подключения_к_mongodb
```

4. **Запустите сервер:**

- В режиме разработки (с автоматическим перезапуском):

```bash
npm run dev
```

- В продакшен-режиме:

```bash
npm start
```

## 🔐 Эндпоинты аутентификации (`/auth`)

Сессии работают через защищённые cookies (`httpOnly: true`, `secure: true`, `sameSite: 'none'`): `accessToken` (живёт 15 минут), `refreshToken` (1 день) и `sessionId` (1 день).

| Метод  | Маршрут          | Описание                                                                | Статус успеха    |
| :----- | :--------------- | :---------------------------------------------------------------------- | :--------------- |
| `POST` | `/auth/register` | Регистрация нового пользователя, создание сессии и установка cookies    | `201 Created`    |
| `POST` | `/auth/login`    | Вход в систему, пересоздание сессии и установка cookies                 | `200 OK`         |
| `POST` | `/auth/refresh`  | Обновление пары токенов и сессии по `sessionId` и `refreshToken` из кук | `200 OK`         |
| `POST` | `/auth/logout`   | Удаление текущей сессии из базы данных и очистка cookies                | `204 No Content` |

## 🚀 Эндпоинты заметок (`/notes`)

> Все маршруты `/notes` защищены middleware `authenticate` и требуют валидной cookie `accessToken`. Каждый пользователь имеет доступ исключительно к своим заметкам.

| Метод    | Маршрут          | Описание                                                            | Статус успеха |
| :------- | :--------------- | :------------------------------------------------------------------ | :------------ |
| `GET`    | `/notes`         | Получить список заметок текущего пользователя (пагинация и фильтры) | `200 OK`      |
| `GET`    | `/notes/:noteId` | Получить заметку текущего пользователя по её `ObjectId`             | `200 OK`      |
| `POST`   | `/notes`         | Создать новую заметку с автоматической привязкой `userId`           | `201 Created` |
| `PATCH`  | `/notes/:noteId` | Обновить заметку текущего пользователя по `ObjectId`                | `200 OK`      |
| `DELETE` | `/notes/:noteId` | Удалить заметку текущего пользователя по `ObjectId`                 | `200 OK`      |

### Параметры запроса для `GET /notes`

- `page` _(необязательный)_ — номер страницы (целое число ≥ 1, по умолчанию `1`).
- `perPage` _(необязательный)_ — количество заметок на странице (целое число от `5` до `20`, по умолчанию `10`).
- `tag` _(необязательный)_ — фильтрация по точному совпадению тега из списка `TAGS`.
- `search` _(необязательный)_ — полнотекстовый поиск по полям `title` и `content`.

**Пример ответа `GET /notes?page=1&perPage=10&tag=Todo`:**

```json
{
  "page": 1,
  "perPage": 10,
  "totalNotes": 1,
  "totalPages": 1,
  "notes": [
    {
      "_id": "6b0979b259c1bf397480cbf3",
      "title": "Buy groceries",
      "content": "Milk, bread, eggs",
      "tag": "Todo",
      "userId": "6b09795b59c1bf397480cbf1",
      "createdAt": "2026-11-27T12:38:10.852Z",
      "updatedAt": "2026-11-27T12:38:10.852Z"
    }
  ]
}
```

### Структура объекта заметки (`Note`)

- `title` _(String, обязательное)_ — заголовок заметки (минимум 1 символ).
- `content` _(String, необязательное)_ — текст заметки (по умолчанию `""`).
- `tag` _(String, необязательное)_ — категория из списка: `Work`, `Personal`, `Meeting`, `Shopping`, `Ideas`, `Travel`, `Finance`, `Health`, `Important`, `Todo` (по умолчанию `"Todo"`).
- `userId` _(ObjectId, обязательное)_ — идентификатор пользователя-владельца (ссылка на модель `User`).
- `createdAt` / `updatedAt` _(Date)_ — автоматические временные метки создания и обновления.
